# 모델 고르는 기준과 성능 측정

강사님 피드백(2026-11-09)을 반영해, 모델을 감으로 고르지 않고 **같은 조건에서 반복해 재고, 기준을 넘는 모델만 쓰기** 위한 문서입니다. 실제로 잰 숫자는 [training-log.md](training-log.md)에 쌓습니다.

## 용어 (처음 보는 분용)

| 말 | 뜻 |
| --- | --- |
| 추론 | 학습이 끝난 모델에 사진을 넣고 답을 받는 것 |
| 정밀도(Precision) | 모델이 "얼룩 있어요"라고 한 것 중 진짜 얼룩인 비율. 시각장애인에게 틀린 말을 하지 않는 정도 |
| 재현율(Recall) | 진짜 얼룩 중에서 모델이 찾아낸 비율. 놓치지 않는 정도 |
| mAP50 | 정밀도와 재현율을 함께 본 종합 점수(0~1). 박스가 절반 이상 겹치면 맞은 것으로 봄 |
| 확신도 | 모델이 답마다 붙이는 0~1 숫자. 우리는 0.5 이상이면 바로 알리고, 0.3~0.5는 지인에게 묻고, 0.3 미만은 버림 |
| FP32 / FP16 / INT8 | 모델 숫자를 몇 비트로 계산하나. 32비트가 가장 정확하고, 16비트·8비트로 줄일수록 빠르고 메모리를 덜 쓰지만 점수가 떨어질 수 있음("인트 체크") |
| TensorRT | 젯슨(NVIDIA GPU)에서 모델을 빠르게 돌리게 바꿔 주는 도구. FP16·INT8 변환도 여기서 함 |
| VRAM | 그래픽 메모리. 젯슨은 CPU와 GPU가 메모리 약 7.5GB를 나눠 씀 |
| 지연(latency) | 사진 한 장을 받아서 답을 돌려줄 때까지 걸린 시간 |

## 통과 기준 (안)

시각장애인 사용자에게는 **틀린 말을 하지 않는 것**이 가장 중요해서, 정밀도와 오탐을 먼저 봅니다. 놓친 얼룩은 지인 확인으로 보완합니다.

| 항목 | 기준 | 지금 v6 (0.5/0.3) |
| --- | --- | --- |
| 바로 알림 정밀도 (얼룩·찢어짐) | **0.90 이상** | 0.70 / 0.81 |
| 깨끗한 옷 오탐 (확신도 0.5 이상) | **1% 이하** | 0.5% (200장 중 1) |
| 재현율 (지인 확인 포함, 확신도 0.3 이상) | **0.60 이상** | 0.59 / 0.69 |
| 옷 종류 정답률 (입은 사진 / 내려놓은 옷) | **0.90 / 0.80 이상** | 약 0.95 / 0.70 (5종 모델) |
| 서버 한 장 전체 처리 시간 (젯슨) | **0.3초 이하** | 측정 예정 |
| 메모리(VRAM) 추가 사용 | **1.5GB 이하** | 측정 예정 |

- 정밀도 0.90은 바로 알림 기준을 0.5보다 올리면(예: 0.6~0.7) 맞출 수 있습니다. 대신 바로 알리는 개수가 줄고 지인 확인이 늘어서, 기준값마다 표를 만들어 고릅니다.
- 재현율 90%는 같은 목적의 논문([Rocha 외, MDPI Sensors 2023](https://www.mdpi.com/1424-8220/23/9/4381), YOLOv5 재현율 0.75)보다 높아 지금 데이터로는 무리입니다.

## 시험 방법

1. **같은 시험 사진**: 얼룩 212개·찢어짐 32개(v2 시험), 깨끗한 옷 200장, 실제 옷 사진 32장, 옷 종류 시험 2,000장, 내려놓은 옷 223장. 학습에 쓰지 않은 사진만 씁니다.
2. **같은 채점 코드**: 모든 모델을 같은 코드로 채점합니다.
3. **3번 반복**: 속도는 3번 재서 평균과 차이를 적습니다. 첫 몇 장은 준비 시간이 섞여서 버립니다(워밍업).
4. **젯슨이 비어 있을 때만**: 학습 중에는 GPU·메모리를 학습이 쓰고 있어서 속도가 틀리게 나옵니다.
5. **방식별로**: PyTorch, ONNX, TensorRT FP32·FP16·INT8 각각 점수, 속도, VRAM, 파일 크기를 잽니다. INT8은 학습 사진 일부로 보정(calibration)합니다.
6. **글로 찾는 모델(OWLv2·Grounding DINO)**: 프롬프트("stain on clothes", "dirty spot on fabric", "hole in shirt" 등)를 바꿔 가며 다시 잽니다.

## 처리 시간 나눠 보기

서버는 요청마다 단계별 시간을 로그로 남깁니다(사진 내용은 남기지 않음).

```
clothes_inspect 1600x1200 laid garments=2 defects=1 candidates=0 | 풀기 40ms, 옷 종류 Nms, 얼룩 Nms, 색·정리 Nms, 전체 Nms
```

- **풀기**: base64 → 사진. 폰 사진(4032×3024)은 긴 변이 1600 이상만 남게 건너뛰며 읽어서 약 70ms → 40ms로 줄였습니다(클라우드 CPU 기준).
- **모델 입력 만들기**: 픽셀을 배열로 바로 읽게 바꿨습니다(512 기준 약 4ms).
- **앞단 딜레이**: 앱은 보내기 전에 사진을 긴 변 1600 정도로 줄여 보내면 업로드와 풀기 시간이 함께 줄어듭니다(앱 담당과 맞출 것). 여러 장을 보낼 때는 다음 사진을 받는 동안 이전 사진을 검사하게 겹쳐 돌립니다.

## 후보 모델 공개 성능 (COCO, 일반 물체 기준)

우리 문제(옷 위 얼룩)와 다른 일반 물체 점수라, 크기·속도를 고르는 참고로만 씁니다. 실제 선택은 위 시험 결과로 합니다.

| 모델 | 크기(파라미터) | COCO mAP50-95 | 속도 (T4 GPU, TensorRT) | 비고 |
| --- | --- | --- | --- | --- |
| YOLO26n | 2.4M | 40.9 | 1.7ms | 지금 v6·옷 종류 모델 |
| YOLO26s | 9.5M | 48.6 | 2.5ms | 한 단계 큰 모델. 정확도↑, 약간 느림 |
| YOLO11n | 2.6M | 39.5 | 1.5ms | 1차 비교에 씀 |
| YOLO11s | 9.4M | 47.0 | 2.5ms | 1차 비교에 씀 |
| OWLv2 base | 약 1.5억 | (글로 찾는 모델) | 맥 GPU 1.0초 | 우리 시험 그대로 쓰면 0.081 |
| Grounding DINO tiny | 약 1.7억 | (글로 찾는 모델) | 맥 GPU 1.8초 | 우리 시험 그대로 쓰면 0.058 |

출처: [Ultralytics YOLO26 vs YOLO11](https://docs.ultralytics.com/compare/yolo26-vs-yolo11). OWLv2·Grounding DINO 속도와 점수는 우리가 잰 값입니다.
