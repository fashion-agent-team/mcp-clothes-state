# 색 조합 규칙 (`outfit_color_check`)

같이 입을 옷들의 **색 조합**과 **오늘 자리에 맞는 색인지**를 봅니다. 학습 모델 없이 규칙으로 판단합니다.
코드는 [`ColorHarmony.java`](../src/main/java/com/fashionagent/clothesstate/color/ColorHarmony.java), 시험은 [`ColorHarmonyTest.java`](../src/test/java/com/fashionagent/clothesstate/color/ColorHarmonyTest.java)입니다.

## 왜 만들었나

2026-11-11 확인 결과, agent는 장례식(어두운 색)·결혼식(흰 상의) 말고는 색을 보지 않았습니다.
그래서 면접에 빨간 바지나 빨간 상의를 입어도, 일정 없는 날 빨강 니트에 초록 바지를 입어도 "잘 맞아요"라고 했습니다.
시각장애인은 색을 스스로 확인하기 어려워서, 이 부분이 앱이 대신 봐 줘야 하는 핵심입니다.

## 왜 학습이 아니라 규칙인가

- **까닭을 말해야 합니다.** "점수 0.4"가 아니라 "빨강 바지는 면접에 튀어요. 검정·네이비·회색 바지가 무난해요"처럼 바꿀 옷과 색을 말해야 합니다.
  옷 조합 모델(Polyvore로 학습한 Bi-LSTM, Type-aware 등)은 점수만 내고 까닭을 말하지 못합니다.
- **자리를 모릅니다.** 공개 코디 데이터에는 면접·장례식 같은 자리 정보가 없습니다.
- **색 조합 기본은 유행을 타지 않습니다.** 반대 색은 튀고, 무채색은 어디에나 맞고, 면접에는 차분한 색이라는 기본은 오래 같습니다.

## 쓰는 값

clothes_inspect가 붙인 `colorFamily`(14가지)와 `tone`(light·mid·dark), `colorName`만 씁니다. 색을 모르는 옷(`unknown`)은 판단에서 뺍니다.

| 묶음 | 색 | 뜻 |
| --- | --- | --- |
| 기본색 | 검정, 흰색, 회색, 네이비, 베이지, 갈색, 카키 | 어떤 색과도 맞음 |
| 강한 색 | 빨강, 주황, 노랑, 초록, 파랑, 보라, 분홍 (진하기 mid·light) | 눈에 띔 |
| 차분한 색 | 강한 색 중 진하기 dark(버건디, 짙은 초록 등) | 기본색처럼 봄 |
| 연한 색 | `colorName`이 하늘색·연분홍·연한 ~ (채도 낮고 밝음) | 기본색처럼 봄 |
| 청바지 | 하의 파랑(mid·dark) | 기본색처럼 봄 |

연한 색은 `tone` 값을 새로 만들지 않고 이름으로 표시합니다. 옷장 DB가 `tone`을 light·mid·dark로만 받기 때문입니다.
GarmentColor는 채도 0.4 미만, 밝기 0.7 넘는 강한 색에 이 이름을 붙입니다.

## 1. 자리 규칙

| 자리 (`occasion`) | 규칙 | 단계 |
| --- | --- | --- |
| 장례식 `mourning` | 검정·네이비·짙은 회색만 괜찮음. 흰색은 상의만 | 그 밖은 bad |
| 결혼식 `wedding` | 흰 원피스 bad. 흰 상의는 어두운 겉옷이 없으면 bad | bad |
| 면접·발표 `formal` | 상의가 강한 색이면 bad(2026-11-11 정지원: 빨간 상의도 바꾸자고). 연한 색 상의(하늘색 셔츠)는 괜찮음 | bad |
| | 하의·겉옷·원피스가 강한 색·연한 색이면 bad | bad |
| | 버건디처럼 어두운 강한 색은 "괜찮지만 차분한 색이 더 무난해요" | note |
| | 신발이 강한 색이면 "조금 튈 수 있어요" | note |
| 출근 `business` | 하의·겉옷이 강한 색이면 "조금 튈 수 있어요" | note |
| 운동·일정 없음 | 자리 규칙 없음. 아래 조합 규칙만 | |

## 2. 옷끼리 조합 규칙

상의·하의·겉옷·원피스끼리 봅니다(신발은 뺌). 같은 종류 옷이 두 벌이면 비교 중인 것이라 서로 조합으로 보지 않습니다.

색상환은 패션·미술에서 쓰는 RYB 색상환입니다(빨강 0°, 주황 60°, 노랑 120°, 초록 180°, 파랑 240°, 보라 300°, 분홍 345°).
화면용 HSV 색상환으로 재면 빨강과 초록이 120°밖에 안 떨어져서 반대 색으로 잡히지 않습니다.

| 규칙 (`rule`) | 언제 | 단계 |
| --- | --- | --- |
| (없음) | 같은 계열, 또는 60° 이내 가까운 강한 색(빨강+주황, 파랑+보라) | good |
| `clash_strong` | 강한 색 둘이 60~150° 떨어짐(빨강+노랑) | note |
| `clash_complementary` | 강한 색 둘이 150° 이상, 반대 색(빨강+초록, 주황+파랑, 노랑+보라) | bad |
| `too_many_colors` | 강한 색이 3가지 이상 | bad |
| `dark_mix` | 헷갈리는 어두운 색끼리(검정+네이비, 네이비+차콜, 검정+짙은 갈색). 손으로는 구분이 안 되는 실수 | info (말하지 않음, [검증](#검증-2026-11-11) 참고) |
| `two_patterns` | 무늬 있는 옷이 두 벌 | note |

사진이 어두우면(`lighting=dark`) 검정·네이비 구분을 믿을 수 없어서 `dark_mix`는 건너뛰고 "어두워서 색이 정확하지 않을 수 있어요"라고 덧붙입니다.

## 3. 말하는 법

- `verdict`: 가장 센 단계. bad가 하나라도 있으면 bad, check·note만 있으면 ok, 없으면 good. info는 세지 않습니다.
- `speech`: 가장 센 것부터 최대 2문장. 같은 옷을 바꾸자는 말은 한 번만.
- 바꿀 옷(`swapGarmentId`): 자리 규칙은 그 옷, 조합 규칙은 하의 → 겉옷 → 상의 순으로 고릅니다. 하의가 가장 바꾸기 쉽고 기본색이 많아서입니다.

예 (실제 출력):

| 옷 | 자리 | verdict | speech |
| --- | --- | --- | --- |
| 흰 셔츠 + 빨강 바지 | 면접 | bad | 빨강 바지는 격식 있는 자리에 튀어요. 검정·네이비·회색 바지가 무난해요. |
| 빨강 니트 + 검정 바지 | 면접 | bad | 빨강 니트는 격식 있는 자리에 튀어요. 흰색·하늘색이나 네이비·회색 같은 차분한 색 니트가 무난해요. |
| 하늘색 셔츠 + 네이비 바지 | 면접 | good | 색 조합이 잘 어울려요. |
| 흰 셔츠 + 베이지 바지 | 장례식 | bad | 조문 자리에는 베이지 바지가 눈에 띌 수 있어요. 검정이나 짙은 회색 바지가 좋아요. |
| 빨강 니트 + 초록 바지 | 일상 | bad | 빨강 니트와 초록 바지는 서로 반대 색이라 많이 튀어요. 초록 바지를 검정·네이비·회색 같은 기본색으로 바꾸면 좋겠어요. |
| 노랑 티셔츠 + 청바지 | 일상 | good | 색 조합이 잘 어울려요. |
| 검정 자켓 + 네이비 바지 | 일상 | good | 색 조합이 잘 어울려요. (`dark_mix`는 issues에만 info로 남음) |

## 도구 입출력

입력:

```json
{
  "garments": [ /* clothes_inspect의 garments 그대로. 지금 사진 옷 + 앞서 본 옷(입기로 한 것) */ ],
  "occasion": "formal",   // mourning | wedding | formal | business | active | casual, 기본 casual
  "lighting": "ok"        // clothes_inspect의 lighting. dark면 dark_mix 건너뜀
}
```

출력:

```json
{
  "verdict": "bad",
  "issues": [
    {"rule": "occasion_formal", "level": "bad", "garmentIds": ["g2"], "swapGarmentId": "g2",
     "say": "빨강 바지는 격식 있는 자리에 튀어요. 검정·네이비·회색 바지가 무난해요."}
  ],
  "speech": "빨강 바지는 격식 있는 자리에 튀어요. 검정·네이비·회색 바지가 무난해요."
}
```

오류: `no_garments`(목록이 빔), `bad_request`(10벌 넘음, occasion 값이 틀림).

## 검증 (2026-11-11)

AI Hub [연도별 패션 선호도 파악 및 추천 데이터](https://aihub.or.kr) Validation 중 **2019년 여성 사진 1,770장**(normcore·lounge·genderless)으로
실제 서버 순서(clothes_inspect worn → outfit_color_check)를 그대로 돌렸습니다. 사진은 긴 변 1024px로 줄였고 레포에는 올리지 않습니다.
스크립트는 [`training/color-bench/`](../training/color-bench/)에 있습니다.

| 항목 | 결과 |
| --- | --- |
| 어두워서 판단 안 함(lighting=dark) | 46장 |
| 몸에 걸친 옷(상의·하의·겉옷·원피스)이 2종류 미만으로 잡힘 | 409장 (23%) |
| 판단한 사진 | 1,315장 |
| 일상(casual) 판정 | good 1,258 · ok 56 · **bad 1** |
| 실제 코디(스타일리스트·런웨이·일반인)에 "바꾸자"(bad)를 잘못 말한 비율 | **0.1%** (1/1,315) |
| `dark_mix`(검정·네이비 등 섞임)가 나온 사진 | 61장 (4.6%) |

**선호도와의 관계는 잴 수 없었습니다.** 2019년 코디는 거의 무채색이라 반대 색·강한 색 조합(bad·note)이 2장뿐이었고,
사진당 응답도 평균 1.3개라 차이를 볼 수 없습니다. 설문 Q5(1·2)의 뜻도 데이터 설명서로 아직 확인하지 못했습니다.

**색 인식을 눈으로 확인**(무작위 24장, 옷 52벌): 색 이름이 맞은 옷 35벌(**67%**).

| 틀린 유형 | 예 | 색 조합 판단에 영향 |
| --- | --- | --- |
| 그늘진 흰 옷 → 밝은 회색 | 흰 셔츠·흰 바지 | 없음(둘 다 기본색). 사용자에게 색 이름을 틀리게 말함 |
| 베이지 → 회색·갈색 | 베이지 패딩 | 없음(둘 다 기본색) |
| 체크·줄무늬 → 엉뚱한 강한 색 | 회색 체크 코트 → 분홍, 파란 체크 자켓 → 빨강 | **있음**: 없는 강한 색을 만들어 냄 |
| 회색 광택 원피스 → 파랑 | | 있음 |

**검정·네이비 섞임(`dark_mix`) 12장을 눈으로 확인**: 실제로 맞은 건 1~3장뿐이었습니다.
연청바지를 네이비로, 어두운 카키를 검정·갈색으로, 네이비 코트를 검정으로 잘못 봤습니다.
틀린 말을 자주 하면 앱을 믿지 못하게 되므로 **`dark_mix`는 말하지 않고 결과(issues)에만 info로 남깁니다.** 색 인식이 나아지면 다시 켭니다.

## 한계와 남은 일

- 색 이름은 픽셀로 정해서 조명이 노랗거나 어두우면 틀릴 수 있습니다(검정↔네이비가 가장 헷갈림).
- 무늬(`pattern`)는 아직 clothes_inspect가 채우지 않아서 `two_patterns`는 지금은 나오지 않습니다.
- 색 인식 개선: 그늘진 흰색, 체크·줄무늬 옷(무늬 인식 결과로 무늬 옷은 강한 색 판단을 약하게), 검정·네이비 구분.
- 선호도 검증은 강한 색 조합이 많은 시대(1980·1990년대 등) 사진으로 다시 해 볼 수 있습니다.
- agent 연결: 확인 단계에서 이 도구를 부르고 `speech`를 판단에 더하는 일은 agent 레포에서 합니다. 약속 문서(mcp-tools.md)에도 도구를 더해야 합니다.
