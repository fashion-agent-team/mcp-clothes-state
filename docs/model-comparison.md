# 얼룩·찢어짐 찾기 모델 비교 (YOLO)

2026-11-05~06, 팀 젯슨(Jetson Orin, 메모리 8GB)에서 학습하고 같은 시험 사진으로 비교한 기록입니다.
결론부터: **지금은 얼룩은 YOLO26n v4, 찢어짐은 YOLO26n v2로 두 모델을 같이 쓰고, 확신이 애매한 것은 지인에게 묻습니다**(아래 4차와 판단 기준). 둘 다 5MB대로 작고 합쳐서 장당 약 30ms입니다. 다만 **옷 전체를 펼쳐 찍은 실제 사진에서는 작은 얼룩을 아직 많이 놓칩니다.** 아래는 1차부터 순서대로 비교한 기록입니다.

## 무엇을 비교했나

- 이 서버가 할 일은 사진 한 장에서 **얼룩(stain)** 과 **찢어짐·구멍(torn)** 을 찾는 것까지입니다. 어떻게 말할지는 agent의 GPT가 정합니다.
- 비교한 모델: Ultralytics YOLO11n, YOLO11s, YOLO26n, YOLO26s (n = 가장 작음, s = 한 단계 큼).
- 클래스 2개: `0 stain`, `1 torn`. 입력 크기 512.
- 점수는 mAP50(박스가 절반 이상 겹치면 맞은 것으로 본 종합 점수, 0~1)을 중심으로 봅니다. P(정밀도)는 "찾았다고 한 것 중 진짜 비율", R(재현율)은 "진짜 중 찾아낸 비율"입니다.

## 1차: 데이터 v1, 30에폭

학습 설정: `imgsz=512 epochs=30 patience=10 batch=16`. 시험은 v1 시험 사진.

| 모델 | 얼룩 P / R / mAP50 | 찢어짐 mAP50 | 속도(장당) | 학습 시간 |
| --- | --- | --- | --- | --- |
| YOLO11n | 0.75 / 0.57 / 0.634 | 0.600 | 14.7ms | 21분 |
| YOLO26n | 0.71 / 0.60 / 0.640 | 0.623 | 14.9ms | 27분 |
| YOLO11s | 0.68 / 0.51 / 0.582 | 0.554 | 20.7ms | 33분 |
| YOLO26s | 0.74 / 0.61 / 0.678 | 0.693 | 23.1ms | 40분 |

- YOLO11s가 n보다 낮은 건 30에폭으로는 덜 배워서입니다(마지막 에폭까지 검증 점수가 오르던 중).
- 찢어짐은 시험 박스가 11개뿐이라 점수를 믿기 어려웠습니다. 그래서 찢어짐 데이터를 더 찾았습니다.

## 2차: 데이터 v2, 60에폭

학습 설정: `imgsz=512 epochs=60 patience=15 batch=16`. 시험은 **v2 시험 사진**이고, 1차 모델도 같은 사진으로 다시 쟀습니다.

| 모델 | 전체 mAP50 | 얼룩 P / R / mAP50 | 찢어짐 P / R / mAP50 | 속도(장당) | 학습 시간 |
| --- | --- | --- | --- | --- | --- |
| 1차 YOLO26n | 0.485 | 0.70 / 0.60 / 0.633 | 0.64 / 0.31 / 0.338 | 15.1ms | - |
| 1차 YOLO26s | 0.558 | 0.69 / 0.64 / 0.674 | 0.69 / 0.44 / 0.442 | 21.3ms | - |
| **YOLO26n v2** | 0.610 | 0.64 / 0.70 / 0.648 | 0.75 / 0.47 / 0.573 | **14.4ms** | 103분 |
| YOLO26s v2 | 0.602 | 0.67 / 0.66 / 0.642 | 0.61 / 0.56 / 0.563 | 21.9ms | 151분 |
| YOLO11n v2 | 0.546 | 0.66 / 0.63 / 0.647 | 0.77 / 0.34 / 0.446 | 14.0ms | 81분 |
| YOLO11s v2 | 0.643 | 0.70 / 0.61 / 0.647 | 0.87 / 0.47 / 0.639 | 20.3ms | 122분 |

- **찢어짐 데이터를 늘린 효과가 컸습니다.** 찢어짐 mAP50이 0.34~0.44에서 0.56~0.64로 올랐습니다.
- 얼룩은 네 모델 모두 0.64~0.65로 사실상 같습니다.
- 네 모델 모두 60에폭을 끝까지 돌았습니다(최고점 에폭: 26n 53, 26s 48, 11n 59, 11s 59). 11 계열은 더 돌리면 조금 오를 수 있습니다.
- 속도는 젯슨 PyTorch FP16 기준(전처리+추론+후처리)입니다.

## 추천과 이유

**YOLO26n v2**를 기본 모델로 추천합니다.

- 위쪽 모델끼리의 0.01~0.04 차이는 시험용 찢어짐 박스가 32개뿐이라 우연일 수 있습니다. 점수가 비슷하면 작고 빠른 쪽이 낫습니다.
- 서버는 GPU 없는 상시 서버에서 돌 가능성이 큽니다. n 모델(5.4MB)이 s 모델(약 20MB)보다 CPU에서 훨씬 유리합니다.
- 잘못 찾는 일을 가장 줄이고 싶다면 YOLO11s v2(찢어짐 정밀도 0.87)가 대안입니다.

## 실제 상황 확인: 펼쳐 놓은 옷 사진 32장

학습에 쓰지 않은 aleminaitha 32장(옷 전체를 바닥에 펼쳐 놓고 폰으로 찍음)에 YOLO26n v2와 YOLO11s v2를 돌려 보고 눈으로 판정했습니다. 원래 박스가 엉성해서 점수 대신 직접 셌습니다.

| | YOLO26n v2 | YOLO11s v2 |
| --- | --- | --- |
| 찾은 수(확신도 0.25 이상) | 28개 / 19장 | 26개 / 13장 |
| 확신도 0.5 이상 | 2개 (둘 다 잘못 찾음) | 4개 (대부분 잘못 찾음) |
| 맞게 찾은 얼룩 | 약 6~8개 | 약 6~7개 |
| 주로 잘못 찾은 것 | 옷의 프린트·로고, 접힌 주름 | 그림자(확신도 높게), 프린트를 찢어짐으로, 무늬 |
| 속도(젯슨) | 장당 30~37ms (세로 사진이라 더 느림) | 비슷 |

**결론: 지금 모델은 "옷 전체 사진"에서는 아직 쓸 수준이 아닙니다.** 두 모델이 비슷하고, 맞게 찾은 것도 대부분 확신도 0.25~0.5라 기준을 0.5로 두면 거의 못 찾습니다. 작은 점 얼룩과 흐린 얼룩은 대부분 놓쳤습니다.

원인은 학습 사진 대부분이 얼룩을 가까이서 찍은 것이라, 옷 전체 사진에서는 얼룩이 512px 안에서 몇 픽셀로 작아지기 때문으로 봅니다.

개선 방법(효과가 클 것 같은 순서):

1. **사진을 4~6조각으로 잘라 조각마다 검사(타일링)**. 재학습 없이 바로 해 볼 수 있습니다.
2. 입력 크기를 512에서 960~1280으로 올려 다시 학습. 작은 얼룩에 유리하지만 느려집니다.
3. 옷 전체 사진과 정확한 박스를 학습 데이터에 추가(팀 촬영).
4. 프린트·그림자·주름만 있는 깨끗한 옷 사진을 "얼룩 없음"으로 추가해 잘못 찾는 일 줄이기.
5. 모델이 애매하게 본 사진만 지인에게 묻기(아래 판단 기준. 처음엔 GPT 비전에 묻는 안이었지만 옷 사진은 GPT로 보내지 않기로 함).

### 재학습 없이 해 본 개선: 타일링과 입력 1024

같은 32장에 두 가지를 더 해 봤습니다. 타일링은 사진을 2x3 조각(20% 겹침)으로 잘라 조각마다 512로 검사한 뒤 합친 것이고, 1024는 자르지 않고 입력 크기만 1024로 올린 것입니다.

| 방식 | 찾은 수 (0.25 이상 / 0.5 이상) | 찢어짐으로 찾은 수 | 찾은 게 있는 사진 | 장당 시간(젯슨) |
| --- | --- | --- | --- | --- |
| 26n 기본 512 | 28 / 2 | 1 | 19장 | 약 37ms |
| 26n 타일 2x3 | 114 / 21 | 18 | 30장 | 196ms |
| **26n 1024** | **57 / 14** | **0** | 22장 | **38ms** |
| 11s 기본 512 | 26 / 4 | 1 | 13장 | 약 33ms |
| 11s 타일 2x3 | 120 / 26 | 8 | 27장 | 175ms |
| 11s 1024 | 103 / 13 | 1 | 29장 | 48ms |

이 32장에는 찢어진 곳이 없어서 "찢어짐으로 찾은 수"는 모두 잘못 찾은 것입니다. 원래 박스가 엉성해 개수보다 경향으로 봐 주세요.

- 두 방식 모두 기본보다 실제 얼룩을 더 잡습니다. 예를 들어 17번 분홍 셔츠의 작은 점, 22·23번 얼룩을 확신도 0.5 이상으로 잡기 시작했습니다.
- 대신 잘못 찾는 것이 더 많이 늘었습니다. 타일링은 바닥·배경 가장자리, 그림자 경계, 로고·프린트(13번 악어 로고, 18번 프린트를 찢어짐으로)에 박스를 많이 칩니다. 5배 느리기도 해서 추천하지 않습니다.
- **YOLO26n v2 + 입력 1024가 가장 무난합니다.** 기본보다 얼룩을 더 찾고, 찢어짐 오탐이 없고, 속도도 거의 같습니다(38ms). 그림자·주름 오탐은 여전히 있습니다.

**정리: 지금 바로 쓴다면 YOLO26n v2를 입력 1024, 확신도 기준 0.5 근처로 돌리는 것이 가장 낫습니다.** 그래도 옷 전체 사진에서 오탐이 남기 때문에, 근본적으로는 위 개선 3·4번(옷 전체 사진과 정확한 박스, 그림자·프린트·주름만 있는 깨끗한 옷 사진)을 학습에 넣고 입력 1024로 다시 학습해야 합니다.

## 3차 시도: 옷 전체 사진 보강 + 입력 1024 (사진 촬영 없이)

팀이 새로 찍을 수 없어서 가진 데이터만으로 해 봤습니다.

- clothes-stain에서 라벨이 비어 있던 원본 517장에 YOLO26n v2로 박스를 자동으로 그리고 한 장씩 검토했습니다. 학습용 365장(박스 715개, 옷 전체 폰 사진 43장 포함)만 넣었고, valid·test에 해당하는 사진은 점수가 부풀려지지 않게 넣지 않았습니다.
- More clothes의 깨끗한 옷 전체 사진(train 67장)에 실제 얼룩을 잘라 작게 붙인 합성 사진 411장(얼룩 박스 약 960개)을 만들었습니다.
- YOLO26n v2에서 이어서 입력 1024로 20에폭 학습했습니다(젯슨 메모리 때문에 batch 4, 155분).

| 모델 | v2 test 전체 mAP50 | 얼룩 | 찢어짐 | 장당 시간 |
| --- | --- | --- | --- | --- |
| 26n v2 @512 | 0.610 | 0.648 | 0.573 | 14.4ms |
| 26n v2 @1024 (학습은 512) | 0.393 | 0.520 | 0.266 | 34.4ms |
| 26n v3 @1024 | 0.613 | 0.664 | 0.562 | 34.5ms |

실제 사진 32장에서 v3는 0.25 이상 22개 / 0.5 이상 4개를 찾았습니다(v2 @512는 28 / 2). 그림자·주름·배경에 치던 박스는 크게 줄었지만, 맞게 찾은 얼룩은 비슷했고 작은 점 얼룩은 여전히 놓쳤습니다. 프린트·로고·옷 라벨을 찢어짐으로 보는 오탐도 남았습니다.

**정리: 오탐은 줄었지만 얼룩을 더 찾지는 못했습니다.** 점수는 같고 2.4배 느리므로 지금 쓸 모델은 여전히 YOLO26n v2(입력 512)입니다. 합성 얼룩이 실제와 달라 보이고, 옷 전체를 찍은 진짜 얼룩 사진이 아직 적은 것이 원인으로 보입니다.

## 4차: 깨끗한 옷으로 오탐 줄이기, 그리고 두 모델 같이 쓰기

옷 쇼핑몰 사진(quocthang, 얼룩 없는 옷 1,592장)을 썼습니다. 200장은 "오탐 시험용"으로 따로 빼 두고, 나머지 1,392장에 YOLO26n v2를 돌려 잘못 잡힌 380장(가죽 재킷을 찢어짐으로, 프린트·로고·배경을 얼룩으로)과 그냥 깨끗한 200장을 "얼룩 없음"으로 넣어 v2에서 이어서 학습했습니다(입력 512). 이것이 YOLO26n v4입니다.

| | v2만 | v4만 | **얼룩 v4 + 찢어짐 v2** |
| --- | --- | --- | --- |
| v2 test 전체 mAP50 | 0.610 | 0.583 | **0.620** |
| 얼룩 mAP50 | 0.648 | 0.667 | 0.667 |
| 찢어짐 재현율 / mAP50 | 0.47 / 0.573 | 0.39 / 0.499 | 0.47 / 0.573 |
| 깨끗한 옷 200장 중 0.5 이상 오탐 사진 | 20 | 2 | 7 (5장이 찢어짐) |
| 깨끗한 옷 200장 중 0.2 이상 뭔가 잡은 사진 | 55 | 25 | 32 |
| 실제 사진 32장: 박스 / 찢어짐 오탐 | 28 / 1 | 18 / 0 | 19 / 1 |
| 장당 시간(젯슨) | 약 15ms | 약 15ms | 약 30ms |

- v4는 깨끗한 옷에서 "얼룩 있어요"라고 확신하는 오탐을 90% 줄였고 얼룩 점수는 조금 올랐지만, 찢어짐을 덜 찾게 됐습니다. 이어서 짧게 학습하는 방식이 찢어짐을 흔들어 놓은 것으로 봅니다.
- 기존 test에는 깨끗한 옷이 10장뿐이라 이 오탐이 점수에 거의 안 잡힙니다. 실제 사용자 옷은 대부분 깨끗하므로 오탐 시험을 따로 둡니다.
- YOLO11s v2를 이어서 40에폭 더 학습해 봤지만 0.643 → 0.574로 떨어져 버렸습니다.

**결정(정지원 2026-11-06): 얼룩은 v4, 찢어짐은 v2로 두 모델을 같이 쓰고, 애매한 것은 지인에게 물어 그 답으로 데이터를 채웁니다.** 기본 모델에서 처음부터 다시 학습한 v5(디자인 찢어짐 옷은 음성에서 빼고 찢어짐 사진 2배)를 진행 중이며, 찢어짐과 오탐 모두 조합보다 나으면 v5 하나로 바꿉니다.

## 판단 기준 제안: 애매하면 지인에게 묻기

실제 사진에서 진짜 얼룩 대부분이 확신도 0.25~0.6으로 나와서, 약속 문서의 첫 기준(0.7 이상만 그대로, 0.5 미만 버림)으로는 거의 다 버려집니다. 그래서 기준을 내리고, 애매한 것은 GPT 대신 helper로 지인에게 묻는 방식을 제안합니다(정지원 2026-11-06, 얼굴 확인의 치아 규칙과 같은 형식).

- **0.6 이상**: 바로 알려 줍니다.
- **0.25~0.6**: "오른쪽 소매 끝에 얼룩이 있을 수도 있어요. 지인에게 물어볼까요?"라고 묻고, 사용자가 원할 때만 helper로 보냅니다. 기다리지 않게 먼저 말하고 답이 오면 알려 줍니다.
- **0.25 미만**: 버립니다.
- 보낼 때는 얼룩 부분만 잘라 보냅니다(입은 사진이면 얼굴·몸이 나가지 않게). 한 벌에 애매한 곳이 여러 개면 한 번에 모아 묻습니다.
- 지인의 "맞아/아니야" 답은 실제 사용 사진의 정확한 라벨이 되므로 학습 데이터로 모읍니다. 답이 쌓이면 0.25~0.6 구간을 좁힙니다.
- **옷 사진은 GPT에 보내지 않습니다**(정지원 2026-11-06). 지인이 없거나 답이 늦어도 GPT로 넘기지 않고, "확실하지 않아요"로 안내합니다.

약속 문서(앱 레포 `docs/contracts/mcp-tools.md`)의 `source: "gpt"` 폴백은 없애고, 지인 확인 값과 확인 대기 상태 표시가 필요합니다.

## 한계

- 시험 사진 대부분이 얼룩·구멍을 **가까이서 찍은 웹 사진**입니다. 우리 앱은 옷 전체를 펼쳐 놓고 위에서 찍으므로 얼룩이 사진 안에서 훨씬 작게 보입니다. 실제 성능은 팀이 직접 찍은 사진으로 다시 확인해야 합니다.
- 깨끗한 옷 사진이 67장뿐이라 무늬·그림자를 얼룩으로 잘못 보는 일은 아직 충분히 시험하지 못했습니다.
- clothes-stain에서 라벨이 빠진 원본 약 900장을 아직 쓰지 않았습니다. 박스를 채우면 얼룩 학습 사진이 늘어납니다.
