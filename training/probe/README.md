# 입은 옷 종류 분류기(probe) 학습 결과

FashionSigLIP 옷 벡터 위에 종류마다 벡터 하나를 학습한 분류기예요. `probe.json`은 서버 GarmentTextCheck가 읽는 모양(garment-text-fsiglip.json과 같은 형식)이에요.

- 학습: 2026-11-15 젯슨 나노(GPU, open_clip fp16), `train_probe.py`
- 스크립트: `make_lists.py`(목록) → `embed_crops.py`(벡터, GPU 또는 `--onnx`) → `train_probe.py`(학습·평가)
- 벡터 파일(npz)은 레포에 넣지 않았어요(젯슨 나노 `~/closet-probe/`에 있음)

| 평가(소스) | 수 | 글 벡터(지금 서버) | 학습 |
|---|---|---|---|
| CC0 내려놓은 옷 | 1019 | 86.8% | 88.1% |
| Fashionpedia 입은 옷(val) | 1831 | 79.0% | 87.5% |
| 빈 벽·배경을 none으로 잡음 | 420 | 95.5% | 99.8% |

옷 빠짐(옷을 none으로 잘못 봄)은 두 방식 모두 0.5%예요.

## 데이터 출처

- clothing-dataset (Alexey Grigorev), CC0: https://github.com/alexeygrigorev/clothing-dataset
- walls: 스크립트로 만든 빈 벽·바닥 그림

## 2차 (probe_v2.json, 2026-11-16)
1차는 정답 박스로 학습해서 실제 서버 박스에서는 글 벡터보다 나빴어요. 2차는 사진을 젯슨 나노의 clothes-state 서버에 그대로 보내 서버가 잡은 박스와 벡터를 받고(`collect.py`), 정답 박스와 IoU 0.3 이상이면 그 종류, 0.1 미만이면 none으로 라벨을 붙였어요. 학습은 지금 글 벡터(35개)에서 출발해 글 벡터 쪽으로 당기는 힘(lambda 0.03)을 두고 다듬었어요(`train_probe3.py`). 파일 모양은 garment-text-fsiglip.json과 같아요.

| 평가(서버 박스) | 수 | 글 벡터만 | 서버 최종 답(검출기+글 벡터) | probe_v2만 |
|---|---|---|---|---|
| Fashionpedia val | 1441 | 83.2% | 87.6% | 91.5% |
| CC0 검증 | 187 | 87.7% | 93.6% | 93.0% |

## 3차 (probe_v3_l*.json, 2026-11-16)
2차 데이터에 드문 종류(니트·가디건·조끼·코트·반바지·셔츠·자켓·치마)가 든 Fashionpedia train 사진의 서버 박스 옷 6,740개를 더했어요. 글 벡터 쪽으로 당기는 힘(lambda)을 4가지로 만들었어요. 2차는 Fashionpedia에서 올랐지만 폰 사진에서 떨어져서, 고르는 건 폰 사진으로 해요.

서버 박스 평가, 모델 확신도 낮을 때 규칙(`rule_eval.py`, 검출기 큰 분류 가산점 0.01+0.005×확신도 = 지금 서버). 값은 큰 분류 / 이름(13개).

| probe_v3_l0.03 | 96.1% / 92.9% | 96.8% / 94.1% |
| probe_v3_l0.3 | 96.0% / 93.3% | 96.8% / 94.7% |
| probe_v3_l1 | 95.8% / 92.6% | 96.8% / 94.1% |
| probe_v3_l3 | 95.7% / 92.8% | 96.8% / 94.7% |

## 5차 (probe_v5_*.json, 2026-11-17) — DeepFashion2 사용, 학교 프로젝트 전용
> **DeepFashion2(비상업 연구·교육용) 사진으로 학습한 결과물, 학교 프로젝트 전용.** 상업적으로 쓰지 마세요. 사진·벡터(npz)·이미지 목록은 레포에 넣지 않았어요(젯슨 나노 비공개 폴더에만 있음).

4차 데이터에 DeepFashion2 **train** 일반인 사진 8,000장(4차와 겹치지 않음)의 서버 박스 옷 11,340개를 더했어요. 이제 DF2 행은 모두 17,048개이고, 학습 행은 모두 33,471개예요. 학습 방법은 4차와 같아요(`train_probe5.py`).

### 폰 사진 평가 (`df2val_eval.py`)
DF2 **validation** 일반인 사진 1,841장(옷 1,908벌)이에요. 학습에 쓰지 않았어요. 사진 대부분(73%)은 검출기 확신도가 0.9 미만이에요. 가산점은 0이고(develop 기본값), 값은 큰 분류 / 세부 13종이에요.

| 파일 | 큰 분류 | 세부 13종 |
|---|---|---|
| 글 벡터 + 가산점 0.01+0.005×확신도 (예전 서버) | 80.2% | 78.2% |
| probe_v4_l0.3_df2x1 (지금 develop) | 81.9% | 81.3% |
| probe_v5_l0.3_df2x1 | 82.0% | 81.3% |
| probe_v5_l0.3_df2x2 | 82.0% | 81.2% |
| **probe_v5_l0.3_df2x3** | **82.4%** | **81.7%** |
| probe_v5_l0.1_df2x2 | 82.2% | 81.5% |
| probe_v5_l1_df2x2 | 81.4% | 80.7% |
| probe_v5_l1_df2x3 | 81.9% | 81.2% |
| 검출기만 | 65.8% | 63.3% |

v5 중에서는 λ0.3, DF2 ×3이 가장 좋아요. 다만 v4보다 0.4~0.5%p(옷 8~9벌) 높을 뿐이라 차이가 작아요. 모든 파일에서 가산점은 클수록 손해였어요(0.03이면 2~3%p 떨어짐). 레포에는 위 표에서 λ0.3 ×3, λ0.1 ×2, λ1 ×3만 넣었어요.

## 7~9차 (2026-11-17) — v4가 왜 틀리는지 보고 고쳐 보기, 결론: 배포 후보 없음
스크립트는 `r7-r9/`에 있어요. 사진, npz, 이미지 목록은 넣지 않았어요. 평가 기준은 폰 사진 1,841장(DF2 validation, 옷 1,908벌)이고, 값은 세부 13종 정답률이에요. FP는 Fashionpedia val(세부)이에요.

**v4 오답 357개**(`conf_v4.py`): 301개는 분류기에서, 56개는 검출기 확신도 0.9 이상인 답에서 나왔어요.
- 원피스→티셔츠: 112개
- 치마→원피스: 31개
- 반팔 상의→원피스: 26개
- 긴팔 상의→자켓: 24개
- 민소매 원피스→치마: 17개

셔츠·티셔츠·니트, 반바지·바지 혼동은 적었어요.

| 방법 | DF2 val | FP val |
|---|---|---|
| probe_v4 (배포) | 81.3% | 92.6% |
| (a) 박스 모양·같은 사진 다른 옷 위치, 선형/MLP64 | 76.6% / 77.4% | 86.8% / 88.1% |
| (a) 애매할 때 원피스↔상의·치마 다시 고르기 규칙(그리드) | 81.3% (안 바뀜) | 92.6% |
| (c) 임베딩 MLP256 잔차, DF2 train만 | 81.4% | 88.8% |
| (a+c) 임베딩+박스 MLP256 | 81.7% | 88.5% |
| (b) (a+c) + 원피스·치마 ×2 | 82.0% | 88.3% |
| (b) 종류별 가산점을 정답률로 맞춤 | 81.6% | 92.4% |
| (c) MLP 잔차, FP·CC0·DF2 train 모두 | 81.0% | 92.2% |
| GPT(gpt-5.4-mini)에게 종류 묻기, 1·2등 차이 < 0.01만 | -0.4%p | - |
| GPT 단독(확신도 낮은 1,389개) | 72.6% (v4 77.6%) | - |

- 이 평가 세트의 박스는 거의 사진 전체예요(높이 중앙값 0.84~0.90, 같은 사진의 다른 옷 0.06개). 그래서 박스·주변 옷 단서가 도움이 안 돼요.
- DF2 train으로 더 학습하면 DF2 val은 오르지만 FP는 떨어져요.
- GPT도 같은 쌍(치마↔원피스, 원피스↔티셔츠)을 많이 헷갈려요. 사진만으로 애매하거나 라벨 기준이 다른 경우가 많아 보여요.
- 그래서 **v4를 그대로 두는 게 좋아요.** 더 올리려면 실제 앱 사진(사용자 폰으로 찍은 내려놓은/입은 사진)과 정답이 필요해요.

## 11차 (2026-11-17) — 더 큰 이미지 모델 비교 (평가만, 배포 안 함)
`r11/`에 스크립트와 결과(`r11_result.json`)가 있어요. 박스는 서버 박스를 그대로 썼고, 자르기는 서버와 같아요(사방 3% 넓힘, 좌우 뒤집기 평균). 각 모델을 두 가지로 쟀어요.
- 글 벡터만: 서버와 같은 35개 글
- v4 방식 학습: 글 벡터에서 시작, λ0.3, 정답 후보 여러 개 허용. DF2 train 5,000개와 Fashionpedia train 5,000개를 썼어요.

시간은 젯슨 나노 GPU fp16에서 박스 하나(좌우 2장)를 처리한 값이에요. 정답률은 세부 13종이에요.

| 모델 | 비전 파라미터 | 박스 1개 GPU | GPU 최대 | DF2 val 글만 / 학습 | FP val 글만 / 학습 |
|---|---|---|---|---|---|
| Marqo FashionSigLIP (지금) | 93M | 30ms | 778MB | 78.0% / 81.3% | 87.8% / 92.6% |
| Marqo FashionCLIP | 86M | 30ms | 575MB | 74.1% / 77.1% | 86.7% / 90.3% |
| SigLIP2 B/16-256 | 93M | 29ms | 1,643MB | 77.0% / 80.6% | 86.7% / 91.9% |
| SigLIP2 L/16-256 | 316M | 103ms | 1,886MB | 81.6% / 82.1% | 87.4% / 93.1% |
| **SigLIP2 So400m/14-224** | 428M | 150ms | 2,382MB | 80.8% / **83.4%** | 87.6% / 92.8% |

- So400m은 학습 후 DF2 val에서 +2.1%p(큰 분류 82.3→84.0%)예요. FP val은 92.6→92.8%로 떨어지지 않았어요.
- 다만 서버는 CPU(ONNX)로 벡터를 만들어요. So400m은 계산량이 지금 모델의 약 5배라 CPU에서는 박스마다 수 초 걸릴 것으로 보여요. 젯슨 나노 메모리도 부족해요. 평가 중 남은 메모리가 0.3GB까지 내려갔어요.
- 옷장 같은 옷 찾기도 같은 벡터를 써서, 모델을 바꾸면 저장된 옷 벡터를 모두 다시 만들어야 해요.

## 12차 (2026-11-17) — So400m 보조 경로가 현실적인지 (평가·측정만)
v4가 먼저 답하고, 아래 두 조건을 모두 만족하는 옷만 SigLIP2 So400m + probe로 다시 판단해요(`r12/r12c.py`, 결과 `r12c_result.json`).
- 검출기 확신도 < c
- v4의 1·2등 점수 차이 < t

| t | c | DF2 val 다시 묻는 옷 | DF2 val 큰/세부 | FP val 다시 묻는 옷 | FP val 큰/세부 |
|---|---|---|---|---|---|
| 0 (v4만) | - | 0% | 82.1% / 81.4% | 0% | 95.3% / 92.6% |
| 0.01 | 0.7 | 11% | 83.2% / 82.6% | 3% | 95.4% / 92.9% |
| **0.015** | **0.7** | **15%** | **83.7% / 83.1%** | **5%** | **95.6% / 93.0%** |
| 0.03 | 0.7 | 26% | 84.0% / 83.4% | 8% | 95.6% / 93.1% |
| 0.03 | 0.9 | 40% | 84.4% / 83.8% | 19% | 95.6% / 92.9% |
| 전부 | 0.9 | 73% | 84.4% / 83.7% | 32% | 95.7% / 93.0% |

옷 15%만 다시 물어도 세부 정답률이 +1.7%p 올라요. 전부 묻는 경우와 차이는 0.6%p예요.

젯슨 나노(Orin Nano 8GB) 측정이에요(`r12b.py`, MemoryMax 2G, 스왑 0).
- 이미지 탑과 글 탑을 함께 올리면 2GB를 넘어서 OOM이 났어요.
- **이미지 탑만 fp16 GPU에 올리면:** 가중치 827MB, 프로세스 RSS 1,945MB, 불러오기 5초예요.
- **처리 시간:** 박스 1개(좌우 2장)에 166ms, 8장 묶음에 576ms예요.
- **글 탑:** 35개 글에 쓰이는 토큰 49개만 남겨 올렸더니 GPU 798MB였어요. 글 벡터는 한 번만 만들면 돼요.
- **int8, ONNX, TensorRT:** 이번에는 재지 못했어요. 2GB 제한 안에서 변환하기 어려워요.
